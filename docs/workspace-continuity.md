# Completed-cut publication continuity

The private IndexedDB resident owner restores publication history from the atomically selected checkpoint. The same checkpoint contains file bytes, namespace metadata, retained mutation receipts, the change suffix, and content-version counters. A receipt keeps its original identity and untracked FAST durability label. Receipts outside the bounded retention remain unknown. Change cursors before the retained suffix return a gap.

The publication decoder rejects fractional, nonfinite, unsafe, negative, and out-of-tail byte indexes before typed-array conversion. Invalid encoded ranges keep filesystem error 29. The selected-record adapter does not add a second range policy.

Recovery creates a fresh authority instance and fresh capabilities. It restores no sessions, pending mutations, tokens, descriptors, grants, or pins. Old descriptors and settlement attempts remain rejected. The explicit `reopen-v1` API deliberately starts a new history and returns unknown for the old history's outcomes. OPFS has no publication-continuity guarantee.

Before publishing ready, the owner durably reserves up to 65536 session IDs through the existing backend flush. A recovered incarnation starts above the saved reserved upper frontier, even when a crash lost an acknowledged mutation from a newer session. Admission fails without mutation when the reservation is exhausted. There is no automatic renewal or retry. Ordinary memory arenas keep their existing 31-bit session ceiling.

Startup pays one durable checkpoint before activation. This cost is separate from mutation acknowledgement. FAST still acknowledges memory publication, not durable storage. An unflushed tail may be lost. The record and its copies are bounded and charged before capture through existing checkpoint and dirty-copy admission. The capture keeps the newest consecutive change suffix that fits the configured checkpoint metadata ceiling after mandatory metadata. This selection does not depend on currently queued captures and does not evict live history. It may keep no changes, so recovery reports a gap for older cursors. Receipts, content versions, and the reserved session frontier are not reduced to fit. If mandatory metadata cannot fit, admission still fails before copying. Held captures retain their full charges until success or failure releases them. This is not a runtime-wide memory bound.

Native bootstrap, continuity, and storage guards still control replacement. A frozen or unresponsive owner is not declared dead. There is no heartbeat lease, automatic election, storage stealing, or public takeover API. The merged last-client lifecycle proof covers explicit reset, not transparent recovery.

`tests/workspace-continuity-browser-runner.ts` uses the real IndexedDB, backend, resident authority, and direct-borrower fixtures. It pauses and resumes the actual worker, refuses a competing owner, observes worker closure, recovers the saved cut, rejects stale capabilities, and checks a post-cut session cannot alias after a crash. It separately measures the startup flush and checks native cleanup after an injected startup-flush failure. Held native storage also checks copy admission and reservation release.

The ordinary `tests/workspace-continuity.test.ts` keeps the pure checkpoint and bounded-suffix recovery unit. `tests/workspace-continuity-checkpoint.test.ts` checks forty sequential default-limit writes and flushes through the actual backend and service, alongside a nonpublication control.

`bun run test:browser` invokes the three native controls once on Chromium through the existing supervisor. They are not registered by `bun run test`. For a focused queued run, use `bun scripts/browser-supervisor.ts 65000 bun tests/workspace-continuity-browser-runner.ts chromium`. Set `STORAGE_SCRATCH_ROOT` to a data-drive scratch directory. `WORKSPACE_CONTINUITY_PORT` can select an explicit free port. Otherwise the test allocates one before starting its server. `WORKSPACE_CONTINUITY_REPORT` selects the evidence file.
